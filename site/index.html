An open-source markdown reader for macOS

A markdown reader
with a memory.

Redline renders the markdown on your disk the way you want it rendered. And because it quietly keeps every version it has ever shown you, it can also answer the question an AI rewrite leaves behind — which four paragraphs moved? — word by word, without touching git.

Get it

Your file is only ever read. Nothing is written next to it, and nothing in it leaves the machine.

A reader first.

GitHub-style rendering, syntax highlighting, tables, task lists and > [!NOTE] alerts. Light and dark follow your system theme, or whichever you pin. Open a file and it stays open — your place in it is kept across reloads, across quits, and across the document being rewritten under you.

Rendered or raw, one key apart

r swaps the prose for the markdown that made it: highlighted, line-numbered, and marked line by line rather than block by block.

Your place survives the swap, because the thing being kept is the line of the file you were on and not the pixel you had scrolled to — which is a different part of the document once the same text is set as prose.

A demonstration: the same passage shown as rendered prose and as highlighted markdown source, with the changed line struck through above the line that replaced it.

Light or dark, diagrams included

mermaid fences render in the page; plantuml fences render to inline SVG locally, never over the network. Both follow the theme, and both are redrawn when you change it rather than left in the colours of the theme you left.

Stages

An event passes through three stages. Each one is idempotent and keyed on the event id, so a replay of any prefix is safe.

Two sidebars, one down each side

The files you have open and every version of this one on the left (⌘B); the document's own headings on the right (⌥⌘B), with the one you are reading under marked as you scroll.

Live reload that keeps your scroll

An editor on one side, Redline on the other, in step. Nothing on the bar says so, because that is the normal state; a red dot appears only if the watch drops.

Links to the file next door work

./api.md, ../adr/0004.md, resolved against the directory your document came out of. Hover one and its destination appears written the way its author would recognise it.

Tabs and no chrome

Several files in one window, one watcher each, each named over its directory so two README.mds are told apart. The window has no OS title bar.

Review mode: the diff is in the prose, not beside it.

No two-column wall to read twice. A changed paragraph gets a thin bar in the left margin, and inside it only the words that actually moved are struck through and tinted — everything else keeps its normal colour, so the document still reads as a document.

Word by word, in place

The word diff runs over rendered HTML rather than markdown source, so marking up an edit never cuts through an emphasis run, a link destination or a fence.

Check a change off as you read it

Click the word in the margin that names it, or press c, and the mark goes — it stops being counted, and n / p walk past it. A heavily edited file is worked down to nothing left.

p99 under 60 seconds. ✓ checked

Every change on the scrollbar

The same three colours down the right edge, at the scale of the whole file. The margin speaks for the screen you are on; the ruler says whereabouts — edited throughout, or three paragraphs near the end.

You choose what since means

Since you last read it, since HEAD, or since any version in the list. m moves the read mark; d puts the marks away for a clean read and forgets nothing while they are gone.

Every version is in a list, and a tracked file arrives with its git history already in it — up to 50 commits, read with --follow so a rename does not end the trail. A row is named by its commit subject, or by the clock time it was saved.

  • A checked-off change survives the document moving around it
